Overview

This project demonstrates a practical SQL and Python workflow for cleaning online retail transaction data and shaping it into a concise reporting layer. The emphasis is not only on producing charts, but on making each transformation rule visible and repeatable.

The challenge

The raw data contained Excel serial dates, missing descriptions and customer identifiers, non-positive quantities or prices, and possible duplicate transactions. These issues had to be identified before revenue or product performance could be interpreted responsibly.

Method

From raw questions to reliable evidence.

01

Audit

Profile missing values, invalid commercial records and exact duplicate groups before changing the data.

02

Selected code

Transparent data-cleaning rules

retail_database_queries.sql · SQLCREATE TABLE Online_Retail_Final AS SELECT DISTINCT * FROM Online_Retail WHERE Quantity > 0 AND UnitPrice > 0 AND Description IS NOT NULL; SELECT ROUND(SUM(Quantity * UnitPrice), 2) AS total_sales_value, COUNT(DISTINCT InvoiceNo) AS total_unique_orders, COUNT(DISTINCT CustomerID) AS total_customers FROM Online_Retail_Final;

Decision log

The choices I made—and why they matter.

  • Exclude records with non-positive quantity or unit price from the analysis table.
  • Require non-null descriptions for product-level reporting.
  • Use DISTINCT for the clean table while preserving the raw data for traceability.
  • Keep database credentials outside the repository through environment variables.

Outcomes

What the evidence produced.

  • Produced 524,878 clean transaction records for repeatable analysis.
  • Analysed more than £10.6M in sales from the validated table.
  • Created reproducible monthly revenue and product-performance outputs.
