UK Retail Transactions

A large retail export was cleaned and organised into a separate analysis table for examining revenue and product performance.

Overview

The workflow uses SQL and Python to inspect the raw transaction data, define cleaning rules and create a separate table for analysis. Each transformation step remains explicit, allowing the process to be repeated without changing the original source.

The challenge

Revenue and product performance could only be analysed after addressing Excel serial dates, missing descriptions and customer identifiers, non-positive quantities or prices, and possible duplicate transactions.

Method

How the project was approached.

01

Inspect

Review missing values, invalid transaction records and exact duplicate groups before changing the data.

02

Prepare

Convert serial dates to SQL datetimes and create a separate clean table without overwriting the raw source.

03

Analyse

Calculate revenue, unique orders and customer counts, then examine monthly revenue and product performance.

04

Present

Connect Python to the cleaned MySQL table and export charts for the final project summary.

Process and outputs

Interfaces, charts and implementation from the project.

Selected code

Data-cleaning rules used in the project

retail_database_queries.sql · SQLCREATE TABLE Online_Retail_Final AS SELECT DISTINCT * FROM Online_Retail WHERE Quantity > 0 AND UnitPrice > 0 AND Description IS NOT NULL; SELECT ROUND(SUM(Quantity * UnitPrice), 2) AS total_sales_value, COUNT(DISTINCT InvoiceNo) AS total_unique_orders, COUNT(DISTINCT CustomerID) AS total_customers FROM Online_Retail_Final;

Main choices

The main choices made in the project.

  • Records with non-positive quantities or unit prices are excluded from the analysis table.
  • Product-level analysis requires a non-null product description.
  • DISTINCT is used for the clean table while the raw data remains available for later reference.
  • Database credentials are managed through environment variables and are not stored in the repository.

Results

Results from the completed project.

  • The final table contains 524,878 cleaned transaction records for repeatable analysis.
  • The cleaned table covers more than £10.6M in sales.
  • Monthly revenue and product-performance outputs can be regenerated from the same workflow.
